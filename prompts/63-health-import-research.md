# A4 · S1 多源健康数据「直接导入我们应用」研究

> 先读 `prompts/00-COMMON.md` 与 `docs/V3_BUILD_PLAN.md` §24，再读本文件。
> **只做研究/文档，不写代码、不改应用。**

## 目标

回答：**每个数据源，用户最少要手动做什么，才能把健康数据直接交给我们的应用？** 终点是「文件直接导入 eclipse health」，不经过三星健康中转。

## 用户已确认的优先级

1. Apple Health 导出
2. 华为 / 小米 / Zepp 导出
3. Samsung Health（仅当用户只有它，兜底）
4. Health Connect：用户未选，可写一小段「是否值得后续支持」的结论，不展开

## 必须研究并写清的内容

对每个源：

- **导出路径**：官方是否提供导出（Apple `export.xml/zip`、华为运动健康、小米运动/Zepp、Samsung Health、Health Connect），在手机/网页/桌面各怎么做；是否需要第三方 App。
- **实际文件格式**：目录结构、XML/CSV/JSON/SQLite/DB 表名与关键字段（步数、心率、睡眠、体重、血压、ECG 等）。
- **转换/解析可行性**：我们能否用 Python 标准库/已装依赖解析；哪些字段不可得；版本差异。
- **用户步骤**：编号步骤（手机导出 → 传到电脑 → 在我们的应用上传），尽量少步骤。
- **合规**：只用官方公开能力或用户自有数据；不逆向私有 API、不破解、不代下载、不绕过付费工具。
- **样本可得性**：是否有公开脱敏样本可测试；没有就明确写「需用户提供」。
- **能力矩阵**：步数/心率/睡眠/体重/血压/ECG 各源能否直接导入、需要什么中间步骤、风险。

同时用一小节回答：

- 酷安/应用商店那类「导入三星健康」工具实际读取哪些源、输出什么中间格式、是网页/桌面/手机端；**只作为线索**，不要求我们复刻。
- 哪些方案必须依赖手机 App 或付费工具，哪些网页端可做。
- 结论：S2 建议先实现哪 1–2 个解析器，为什么。
