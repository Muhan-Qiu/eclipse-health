module contract v2

Build a module

A module is a separate Python process that talks to the core over stdio JSON-RPC. The core never imports module code; data, permissions and UI all pass through restricted interfaces. This page is the shortest path that works.

Sources of truth: schemas/module.schema.json and docs/MODULE_CONTRACT_V2.md. If documentation and implementation disagree, the schema wins.

1 · Contract overview

The contract has a transport layer and a contribution layer. Transport makes a module startable, callable and auditable; contributions tell the core what the module offers.

Transport: JSON-RPC over stdio

One JSON document per line. Request {"jsonrpc":"2.0","id":1,"method":"...","params":{}}; a single message is capped at 4 MB, and large results are written to a temp file with a path and sha256.

Lifecycle

discover → verify → install → start → initialize → operate. The core injects ECLIPSE_MODULE_ID, ECLIPSE_RPC_TOKEN and ECLIPSE_PERMISSIONS.

Contributions are declarative

contributes is validated at install time. UI renders controlled components only; arbitrary React/JSX, inline scripts and iframes are forbidden.

The module type determines which contributions are required: device-adapter needs importFormats; signal-engine needs pipelines; analysis-model needs models; dashboard-widget needs ui.widgets; exporter needs exporters; ai-tool needs tools.

2 · .ehmod package layout

An .ehmod is a ZIP archive. Installing checks for path traversal, symlinks, file count and unpacked size.

Directory layout
my-module/
├── module.json          # required: manifest
├── src/
│   └── main.py          # required: the file entry.python points at
├── models/              # optional: ONNX / safetensors weights
├── ui/                  # optional: declarative UI resources
├── LICENSE              # required: full licence text
├── NOTICE               # required when Apache-2.0 and similar licences demand it
├── README.md            # recommended: usage, permissions, data sources
└── checksums.json       # generated at pack time: per-file sha256
  • Installed to <dataDir>/modules/<id>/<version>/; the directory is treated as read-only.
  • Single file ≤ 64 MB, unpacked ≤ 256 MB; symlinks, absolute paths, .. and Windows reserved device names are rejected.
  • Release packages must include checksums.json; files are verified at install, and a missing file degrades to a warning.
  • Never pack venv/, __pycache__/, .git/ or any secret.

3 · module.json example

This manifest validates against schemas/module.schema.json. Change the ID and entry point and it is ready to use.

module.json · schema 1.0 
{
  "schemaVersion": "1.0",
  "id": "io.github.example.heart-rate",
  "name": "Heart Rate Summary",
  "description": "Summarize heart rate from user-selected CSV files. Not a medical device.",
  "version": "0.1.0",
  "apiVersion": "1.0",
  "engines": { "eclipse": ">=1.0 <2.0" },
  "type": "ai-tool",
  "author": { "name": "Example Author", "url": "https://github.com/example" },
  "license": "MIT",
  "homepage": "https://github.com/example/heart-rate",
  "repository": "https://github.com/example/heart-rate",
  "permissions": ["files:user-selected", "records:write"],
  "dependencies": ["numpy>=2.0,<3"],
  "entry": { "python": "src/main.py", "factory": "create_module" },
  "contributes": {
    "tools": [
      {
        "id": "hr.summary",
        "name": "Heart rate summary",
        "description": "Return mean and max heart rate from a CSV file.",
        "inputSchema": {
          "type": "object",
          "properties": { "path": { "type": "string" } },
          "required": ["path"]
        }
      }
    ],
    "ui": {
      "widgets": [
        {
          "id": "hr-latest",
          "title": "Latest heart rate",
          "size": "sm",
          "dataSource": { "type": "module-rpc", "method": "summary" },
          "view": { "type": "stat", "valuePath": "mean", "unit": "bpm" }
        }
      ]
    }
  },
  "resources": { "memoryMb": 256, "cpu": 0.5, "startupTimeoutMs": 8000 },
  "updateChannel": "stable"
}

Community module IDs must be io.github.<GitHub username or org>.<module-name>; the org.eclipsehealth.* prefix is reserved for project maintainers.

4 · Permissions

Request only the minimum set you actually need. New permissions on upgrade must be re-approved by the user and are never inherited automatically.

ScopeRiskMeaning
records:readLowRead records, measurements and analysis results
records:writeMediumCreate or update records
records:deleteHighDelete records; never granted by default
files:user-selectedLowRead files the user explicitly chooses
files:exportMediumWrite to a directory the user confirms
networkHighAccess hosts listed in allowedHosts
llmMediumCall the LLM the user configured
models:downloadMediumDownload model weights
ui:customHighCustom UI inside a sandbox
system:notifyLowSend system notifications
system:backgroundMediumKeep running when minimised

Declaring network requires allowedHosts, and every host must be a concrete domain — the wildcard * is forbidden.

5 · Dependencies and network

  • Each module gets its own venv; dependencies is a PEP 508 list installed into that environment.
  • Only package names, extras, version ranges and environment markers are accepted. Rejected: URLs (@), local paths, file: and -e forms.
  • Pin versions or set a sensible upper bound so upstream major releases cannot break you; the first install goes online and the user must know.
  • models allows onnx / safetensors / remote only; pickle is forbidden. Remote weights must carry a sha256.
  • API keys and tokens go into the OS keychain, never into logs, the manifest or the package.
Accepted and rejected dependency forms 
# accepted
"numpy>=2.0,<3"
"heartpy==1.2.7"
"pandas[performance]>=2.2 ; python_version >= '3.12'"

# rejected (CI and the installer both block them)
"https://example.com/pkg.whl"
"git+https://github.com/owner/repo"
"-e ../local-package"
"../../somewhere"

6 · Test checklist

Complete at least these checks before opening a PR; CI re-runs the structural and packaging validation.

  • module.json validates against schemas/module.schema.json.
  • Empty stdin, unknown methods and invalid params all return structured JSON-RPC errors — no crash, no hang.
  • After startup, send initialize and confirm it returns moduleId and apiVersion.
  • Run the main path against a temp directory; never read real user health data and never log waveforms or filenames.
  • Offline, timeout and empty-data cases return clear error codes; large results use temp files.
  • After packing, unpack in a clean directory and run once to confirm no paths outside the package are required.
Local validation (example paths)
python -m json.tool module.json
python -m pip install jsonschema
python .github/scripts/validate_module.py marketplace/submissions/my-module

7 · Submitting a PR

  1. Fork the repository and add module.json, src/, LICENSE (plus NOTICE for Apache-2.0) and README.md under marketplace/submissions/<module-id>/.
  2. Run the validator and packer locally; confirm the .ehmod unpacks and its checksums match.
  3. Fill in the PR template (.github/PULL_REQUEST_TEMPLATE/module.md): author, licence, upstream, permissions, tests, screenshots and the non-diagnostic notice.
  4. CI validate-module checks schema, path safety, the licence allowlist, NOTICE and package integrity; a failure blocks merge.
  5. After merge, a maintainer uploads the .ehmod to GitHub Releases, then regenerates and signs the index offline.

8 · Licences and attribution

The official index accepts OSI licences only; the community index allows proprietary or paid modules but they must be clearly labelled. The CI allowlist rejects AGPL and unlicensed submissions.

LicenceOfficial indexRequirement
MIT / ISC / BSD-2-Clause / BSD-3-ClauseAllowedKeep the copyright notice and full licence text
Apache-2.0AllowedKeep LICENSE and NOTICE, mark modifications
MPL-2.0AllowedModified files must be published
GPL-2.0 / GPL-3.0 / LGPLAllowedIsolated over stdio JSON-RPC; never statically linked into the core
AGPL / SSPL / BUSL / no licenceRejectedConflicts with the distribution model or right to redistribute cannot be established
  • Keep upstream LICENSE/NOTICE files and never strip copyright headers; state the upstream repository, original copyright holders and your changes in README.md and the description.
  • The author field names the adapter maintainer and must not imply upstream endorses your module.
  • Prefer wrappers (subprocess or library calls). If you must patch, keep the original licence and publish the modified source.
  • Record model weights and code licences separately: source URL, SPDX identifier, sha256 and scope.

9 · Security and non-diagnostic notice

Put this in every module description

"This module is not a medical device. Its output is not for diagnosis or treatment." Any description claiming diagnosis, cure or replacement of a doctor is flagged as high risk and may be rejected.

  • Never pack API keys, private keys or tokens; CI scans for common secret patterns.
  • No downloading and executing arbitrary code, no obfuscation, no pickle deserialisation and no suspicious network requests.
  • Health data stays local by default; going online requires network and is explained permission by permission on the install page.
  • Logs must not contain waveforms, user notes or original filenames — IDs and hashes only.
  • Community modules are not manually reviewed: the install page shows "unreviewed, use at your own risk".
