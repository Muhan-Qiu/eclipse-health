One import, from waveform to report

From ECG and health-data import through analysis, records, trends and reports — all on this machine.

ECG import

WFDB, CSV, EDF and SCP-ECG, plus ECG exports from Apple Health, Samsung and Huawei watches (vendor formats marked experimental). Drag and drop, with a preview and parameter check before import.

Beat analysis

The built-in Cardia 2.0 engine reports signal quality, R peaks, per-beat N / SVEB / VEB / F classes and heart-rate/interval measurements. Switch engines and re-analyse at any time.

Records and trends

Filter the record library by time, device and tag; zoom and pan waveforms; follow metric trends and compare two records side by side.

Reports and sharing

Generate PDF / PNG reports with redaction and a "non-diagnostic" watermark. Reports stay on your machine and can be exported when you choose.

AI assistant (optional)

Connect OpenAI, Anthropic or a local Ollama instance. API keys live in Windows Credential Manager; only summaries and measurements are sent, and every tool call is visible.

Local and open

Data lives in local SQLite with no telemetry. A local REST API, an OpenAI-compatible endpoint and MCP let other applications and AI tools use it.

First-party analysis modules

Official modules follow the same contract as third-party ones. Here is what each of them actually does, before any model talk.

Cardia 2.0 · built-in beat classification

Ships with the app

The ECG engine you can use the moment the app opens.

Classifies single-lead ECG beats as N / SVEB / VEB / F and reports signal quality, heart rate and interval measurements. No module install — it comes with the core.

  • Beat-by-beat arrhythmia classes
  • Signal quality and heart-rate / interval measurements
  • Switch engines and re-analyse in the app
Download the app →

ECG Beat Analysis

First-party · optional module

Splits an ECG into beats and flags normal beats and ectopics.

Seven classification models run on the same recording so you can switch or compare side by side. Outputs per-beat labels, class proportions and a heart-rate overview — built for research replication and algorithm comparison.

  • Per-beat N / SVEB / VEB / F labels
  • Seven models to switch and compare
  • WFDB, float32 and inline sample input
View module details →

Sleep Staging

First-party · optional module

Assigns an entire night to five stages and shows the structure.

Labels each window as W / N1 / N2 / N3 / REM and summarises time per stage, awakenings and sleep efficiency. Accepts extracted features or raw 30-second windows, with five models to compare.

  • Five-stage sleep classification
  • Whole-night structure summary
  • Five staging models to compare
View module details →

Modules are first-class, not easter eggs

The core stays minimal: data, permissions, lifecycle and audit. Everything else can be replaced.

Separate processes

Modules speak stdio JSON-RPC and never import core code. A crash is isolated, and any module can be disabled at any time.

Least privilege

Reading records, writing records, network and background execution are granted permission by permission. New permissions on upgrade require explicit re-approval.

Declarative UI

Pages and widgets use only controlled components and design tokens. Arbitrary React or CSS is limited to sandboxes and theme scopes.

Removable and replaceable

First-party features ship as modules too: preinstalled but removable. Users can pin versions and switch between stable and beta channels.

Security boundaries, stated up front

Publishing runs structural, integrity, dependency, static-code, secret, permission-diff, network-allowlist and model-format scans. Red refuses installation; yellow and orange allow it but are clearly labelled. The client sends no telemetry, does not report installed modules, and health data does not leave this machine by default. All analysis output is non-medical and not for diagnosis or treatment.
